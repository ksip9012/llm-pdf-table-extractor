# 0004. 出力と正解は、見出しの組でセルを対応させ、値・単位・注記を分けて比べる

- Status: Accepted
- Date: 2026-11-03

## Context
[0002](./0002-truth-as-long-cells.md) で正解を縦長の形にし、[0003](./0003-gemini-with-single-page-pdf.md) で LLM にも同じ形で出させた。次は、LLM の出力と正解を比べて精度を数える。決めることは次の 3つ。

1. 出力のセルと正解のセルを、何で対応させるか
2. 値の書き方の違い（「1,000.00」と「1000.00」、全角と半角など）を、どこまで同じとみなすか
3. 何を数えるか

表 1-1 を実 API で 1回取り出したところ、見出しの組・値・注記はすべて合い、違いは単位だけだった（正解の側が「‰」で、PDF と xlsx の「0/00」と違っていた。正解を直した）。

## Decision
出力と正解は、行の見出しと列の見出しの組でセルを対応させ、値・単位・注記を分けて比べる。

- 対応させるキーは `(row_label, column_label)`。見出しは前後の空白を外し、Unicode の NFKC で揃えてから比べる（全角の数字・英字と半角を同じにする）
- 値は、NFKC で揃えて桁区切りのカンマを外し、どちらも数値として読めるなら数として比べる（「1,000.00」「1000.00」「1000」は同じ）。読めない値（「-」など）は文字列のまま比べる
- 単位は NFKC で揃えた文字列、注記は番号の集合で比べる
- 数えるもの
  - 値の一致率: 値が合ったセルの数 ÷ 正解のセルの数（主な指標）
  - 桁まで合ったセルの数: 値が合ったうえで、カンマを外した文字列としても同じもの（「1000.00」と「1000」は値は合うが、桁は違う）。0002 で値は PDF に書かれた桁で持つと決めたので、桁を落とした誤りも見えるようにする
  - 足りないセル（正解にあって出力にない）と、余計なセル（出力にあって正解にない。同じキーが 2回出たときの 2回目も含む）
  - 単位・注記の食い違い
  - すべて（値は桁まで・単位・注記）が合ったセルの数
- 食い違いは 1つずつ一覧にして出す（どのセルの、何が、正解と出力でどう違うか）

## Consequences
- 値の一致率を主な指標にするので、表ごと・渡し方ごと・モデルごとに 1つの数で並べられる。単位や注記の誤りは、値の一致率を下げずに別に数える
- 「1000」と「1000.00」は値の一致率では同じとみなす。小数の桁を落とした誤りは、値の一致率を下げずに、桁の食い違いとして別に数える
- 見出しの表記ゆれ（「北海道」と「北 海 道」、異体字など）は NFKC では揃わず、足りないセルと余計なセルの両方に出る。どれくらい起きるかを見て、必要なら見出しの対応のさせ方を別の ADR で決める
- 選ばなかった案: 文字列の完全一致だけで比べる（「1,000.00」のような書き方の違いと、値の誤りが区別できない）、すべての列が合ったときだけ一致とする（単位の書き方 1つで表全体が 0点になる）
