# 0001. 表ごとの xlsx はリポジトリに入れ、本全体の PDF は落として使う

- Status: Accepted
- Date: 2026-11-03

## Context
総務省統計局「日本の統計 2026」の、本全体の PDF（約 3.4MB）を入力にし、同じ表の xlsx（表ごとに 20KB ほど）を正解の元にする。元データをリポジトリに入れるか、使うたびに落とすかを決める必要があった。

2026-11-03 に確かめると、次のように残り方が違った。

- 本全体の PDF: 2026 年版のほかに、2025 年版・2024 年版もサイトに残っている
- 表ごとの xlsx: 表 1-1 の 2025 年版（`n250100100.xlsx`）は 404 で、新しい版が出ると消えるようだった（1つの表で確かめただけ）

xlsx が消えると、あとから同じ正解で精度を測れなくなる。

利用規約は公共データ利用規約 第1.0版（PDL1.0。CC BY 4.0 と互換）で、出典を書き、加工したことを明記すれば、元データも作ったデータも公開できる。

## Decision
- 表ごとの xlsx はリポジトリに入れる（`data/xlsx/2026/`）
- 本全体の PDF はリポジトリに入れず、`mise run fetch` で落として `data/raw/`（git の対象外）に置く
- どちらも `data/sources.toml` に URL と sha256 を書き、落としたファイルが一覧と同じかを sha256 で確かめる
- xlsx から作る正解（整然データ）は、作ったらリポジトリに入れる
- README に出典（サイト名・URL）と、加工したことを書く

## Consequences
- 小さく、消えやすい xlsx は手元にあるので、サイトから消えても同じ正解で測れる
- PDF はリポジトリを大きくしない。サイトの PDF が差し替わったら、sha256 が合わずに止まるので気づける
- 章を広げて xlsx が増えても、1表 20KB ほどなので、リポジトリはそれほど大きくならない
- 選ばなかった案: PDF も xlsx も入れる（PDF の版が増えるたびに大きくなる）、どちらも入れずに落とすだけ（xlsx が消えると正解が作れない）
