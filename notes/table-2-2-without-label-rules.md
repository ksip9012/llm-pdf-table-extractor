# 列の見出しの書き方の決まりを外したときの表 2-2（2026-11-03）

Step2 の 4表は、すべて値の一致率 100% だった。ただし、プロンプトの列の見出しと単位の書き方の決まり（[decisions/0006](../decisions/0006-multi-level-column-labels.md) の部分）は、表 2-2 の正解の形を決めたあとに書き足したもの。決まりを伝えなかったとき、どれくらい正解とずれるかを見た（#26）。

## 測り方

- 表 2-2 を、決まりを外したプロンプト（`--variant without-label-rules`）で 1回取り出した。出力は `data/output/variants/without-label-rules/2-2.csv`
- 外したのは、PR #27 で書き直した 2つの決まりだけ。その部分を PR #27 より前の書き方に戻した
  - 外した: 列の見出しを上の段から「/」でつなぐ決まり／単位は単位の行と表全体をまとめる見出しのものだけで、列の見出しと同じ枠のかっこ書きは column_label に残す決まり
  - 戻した書き方: 「列の見出しに単位が書かれていれば、単位は unit に書き、column_label からは外す。複数の列をまとめる見出しに単位が書かれていれば、その下の列すべての unit に書く」
  - ほかの書き方（値の桁、注記、見出しの改行を外すなど）はそのまま
- 既定のプロンプトは変えていない（PR #27 のものと一字一句同じことを確かめた）
- 比べ方は [decisions/0004](../decisions/0004-compare-cells.md) のまま。加えて、列を左からの順番で正解の列に対応させたときに、値・単位・注記が合うかも数えた（この notes のためだけの集計）

## わかったこと

- 決まりを外すと、値の一致率は 100% から 0% に落ちた。ただし値を読み違えたセルは 1つもない。列を順番で対応させれば、値は 384 セルすべて合っていた
- ずれは 2つだけで、どちらも「見出しをどう書くか」の違い
  - LLM は列の見出しのいちばん下の段だけを書き、上の段（「国勢調査人口」「令和6年推計人口」）をつながなかった
  - 「（人口1,000につき）」を単位とみなして unit に移した（正解は column_label に残す）
- 比べる仕組み（0004）は、見出しの組でセルを対応させるので、列の見出しが 1文字でも違うと、その列のセルはすべて「足りない」と「余計」の両方に数えられる。今回のように、値が読めていても一致率は 0% になる
- 決まりを外すと思考のトークンが 8倍（1,300 → 10,438）になり、時間と料金も増えた。見出しの書き方を LLM が自分で決めようとして考えた分と推定（中身は見ていない）
- Step2 でわかったことをまとめると、この PDF の表では、LLM は値をほぼ間違えずに読める。精度の差は「値を読めるか」より「正解と同じ形で見出しを書けるか」で出る。形の決まりをプロンプトで伝えれば守れるが、伝えないと、値が合っていても見出しの組で比べる評価では 0% にもなる

## これからに向けて（案）

- 評価を、見出しの組の完全一致だけでなく、「列の対応を見つけてから値を比べる」形でも出すと、読み取りの精度と書き方のずれを分けて示せる（今回は notes のための集計だけで、仕組みには入れていない）
- 正解の形の決まりを、表を見る前にプロンプトとして決めておけば、表に合わせて決まりを書き足す（後出しになる）ことを避けられる
